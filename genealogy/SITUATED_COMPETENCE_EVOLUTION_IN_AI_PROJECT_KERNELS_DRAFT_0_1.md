# Situated Competence Evolution in AI Project Kernels

## A falsifiable framework for contextual reentry, causal readback, and open-ended learning

## Abstract

Language-model agents can interleave reasoning and action, retain memories,
reflect on feedback, accumulate executable skills, and even modify agent code.
These advances leave a practical gap at the scale of a changing project: how
can an AI system preserve the causal trajectory of the work, make the right
operating knowledge pertinent to the present situation, and let the result of
real work change how a later, non-identical situation will be handled?

This paper introduces the **AI Project Kernel** as an operational framework
that couples a present project field, a possibility horizon, situated
competences, a concrete resultant, causal readback, owner-local learning, and
contextual reentry. A competence is not identified with a prompt, skill file,
capability label, or model parameter. It is an owner-native faculty that
understands its domain and its participation in the wider system, acts in a
situation, reads the causal difference produced by its result, and can change
the method through which it will act later. The framework is represented as a
field transition

```text
F_n + P_n + C_n -> M_n -> R_n -> Delta C_n -> F_(n+1),
```

where the composition `M_n` is recognized in the event rather than imposed by
a permanent central controller. We derive falsifiable hypotheses for
trajectory-aware contextual return, competence assimilation across
non-identical tasks, and event-local composition. We specify comparisons
against retrieval, extended prompting, explicit state machines, fixed skill
routers, and base-model performance. The public MAIOS Project Kernel is
presented only as an inspectable reference incarnation; its architecture and
tests do not establish the behavioral hypotheses. The term *awareness* is used
only as a candidate operational construct and carries no claim of phenomenal
consciousness or sentience.

## 1. Introduction

An agent working inside a real project rarely encounters a sequence of
independent prompts. The project already has identity, sources, decisions,
unresolved pressures, other participants, and a history of effects. A useful
action changes some of those relations. When the agent returns, continuing
correctly requires more than recalling text: it must recover which relations
remain live, which events changed the object, and which operating knowledge is
now pertinent.

Current agent research supplies several parts of this problem. ReAct
interleaves reasoning and action [1]. Reflexion retains linguistic feedback
across trials [2], while Self-Refine iterates feedback and revision within a
generation process [3]. Generative Agents synthesize memories into reflections
used for planning [4], and MemGPT manages multiple context tiers for extended
interactions [5]. Voyager accumulates and reuses executable skills from
environmental feedback [6]. Automated Design of Agentic Systems and the Darwin
Gödel Machine explore changes to agent architectures or code under evaluation
[7, 8].

The framework proposed here asks a different, complementary question:

> Can a project-level AI system preserve a changing causal field and let the
> result of situated work change the competence through which later,
> non-identical work will be performed?

The paper makes four contributions.

1. It defines a **competence** as a situated, causally learning faculty and
   separates it from its files, prompts, host adapters, and model capacity.
2. It gives a compact transition model connecting context, possibilities,
   event-local competence composition, resultants, learning, and reentry.
3. It proposes an assimilation criterion: a competence change is behaviorally
   meaningful only when it changes a later non-identical case beyond what the
   same stored correction or added prompt explains.
4. It provides an experimental programme with strong alternative explanations
   and explicit falsifiers.

The primary object is a research framework for academic scrutiny. Possible
software condensates, guides, or interactive public forms are downstream
projections and are not required for the argument.

## 2. Research object and definitions

### 2.1 Project field

Let `F_n` denote the present project field at event `n`: the project identity,
qualified sources, relevant trajectory, current objective or pressure,
material constraints, known unknowns, and effect authority that are jointly
true at that moment. `F_n` is not the complete transcript and is not a bag of
retrieved passages. It is the smallest causally sufficient relation from which
the current work can proceed.

Let `P_n` be the possibility horizon still reachable from `F_n`. The horizon
includes source-near possibilities and relations that may become visible only
through composition during the event. Keeping a possibility open does not
mean refusing a determinate result. Once the field produces a form, that form
belongs to the next present unless later evidence changes it.

### 2.2 Competence

A competence is owner-native operating knowledge able to carry awareness of a
domain into situated action and to continue differently after reading the
causal result of its own work. Its potential dimensions are:

- **situated**: it understands the actual object and qualified sources of its
  domain;
- **self-reflective**: it reads the difference introduced by its movement;
- **systemically aware**: it understands its participation in the wider
  project without absorbing other owners;
- **autological**: it can make its own method an object when that relation
  becomes material;
- **meta**: it can compose, form, or evolve competences;
- **autopoietic in the operational sense used here**: real use can change the
  owner-native form through which future work occurs.

These dimensions are not stages, a maturity score, or claims about subjective
experience. A skill document, executable function, prompt, state record, or
model adapter may project a competence without exhausting or proving it.

### 2.3 Resultant and causal readback

`M_n` is the set of competence relations made pertinent by the event. It is not
assumed to be a fixed stack selected by an external planner. It may be a single
competence or a temporary composition recognized because the present object
requires relations from several owners.

`R_n` is the resultant: a concrete change in the selected object, or a genuine
decision not to collapse the field when no faithful result is available.
A successful tool, repository, or provider operation is evidence inside the
event, not proof of the project-level resultant unless the intended object
relation and every projection included in the claim have become coherent.
`Delta C_n` is the reusable causal difference attributed to the closest owner.
It is not a summary of everything that happened. It records what a competence
must do differently, why, under which conditions, and what would invalidate
the change.

The proposed transition is:

```text
F_n + P_n + C_n -> M_n -> R_n -> Delta C_n -> F_(n+1)
```

where `C_n` is the available competence field and `F_(n+1)` includes the
resultant, the competence delta, and relations deliberately left open.

### 2.4 Contextual reentry

Contextual reentry is the recovery of an earlier relation from a present that
has been changed by intervening events. If a conversation or project moves
from subject `A` through event `E` and later returns to `A`, a faithful reentry
is not `retrieve(A)`. It is:

```text
K_t = compose(A, consequential(E), current objective,
              current sources and owners, conditions at time t).
```

The components may each be correct while never having been jointly true.
Reentry therefore requires a coherent cut of the field rather than maximal
recall.

## 3. Relation to prior work

ReAct demonstrates the value of coupling reasoning traces to actions and new
observations [1]. The Project Kernel framework takes that coupling as an event
mechanism but asks how its causal consequences alter project-level continuity
and later competence.

Reflexion stores verbal reflections from feedback for later trials [2], and
Self-Refine uses a model's feedback to improve its own output iteratively [3].
The present proposal requires a stricter ownership and transfer test. A stored
reflection is evidence of availability; competence assimilation is claimed
only when the correction changes a later non-identical case without being
reconstructed as the same episode.

Generative Agents combine observation, reflection, retrieval, and planning to
produce persistent behavior [4]. MemGPT addresses long interaction histories
through virtual context management [5]. Both make continuity technically
tractable. The Project Kernel hypothesis concerns which causal relations must
be selected together, how irrelevant history is excluded, and how the result
changes an owner-native operating method.

Voyager is the closest precedent for a growing, reusable skill field: it
creates executable programs from environment feedback and retrieves them for
new tasks [6]. The competence construct is broader but also more demanding. It
may include code, method, interpretation, provenance, and effect boundaries;
its value must be shown in later situated behavior rather than inferred from
library growth.

ADAS searches code-defined agent designs with a meta-agent [7]. The Darwin
Gödel Machine modifies agent code, retains diverse lineages, and evaluates
changes empirically [8]. These systems make architecture evolution an explicit
search process. In the present framework, ordinary evolution is distributed:
the competence that acts is the first owner of the learning produced by its
result. A central architecture mutation is a separate possibility, not the
default consequence of every useful event.

The term *autopoietic* originates in theories of self-producing living
organization [9]. This paper uses it only for a bounded operational analogy:
some system processes may reproduce or change the competences through which
later system processes occur. It does not claim biological autopoiesis,
organizational closure, life, or consciousness. If the analogy adds no
discriminating value, it should be removed without affecting the empirical
hypotheses.

## 4. Kernel movement

### 4.1 Aperture without indeterminacy

The framework includes an aperture condition: the system must not transform
the limits of its current context, schema, tool, skill catalogue, or first
interpretation into limits of the object itself. This condition preserves
unrepresented possibilities, but it does not reopen a result merely because
the result is explicit or surprising. Provenance, current facts, and authority
remain binding relations.

### 4.2 Situated composition

Competence routing is treated as circulation through the relations that can
change the present resultant. The empirical question is not whether a router
file exists, but whether the system can avoid two symmetric failures:

1. selecting the nearest represented skill and collapsing relevant relations;
2. activating meta-level machinery that adds latency without changing the
   result.

An event-local composition should therefore be compared with a fixed router
under identical models, tools, and sources.

### 4.3 Owner-local evolution

When a result exposes a reusable causal correction, the smallest competence
that owns the affected behavior changes first. This avoids treating one
central Kernel document as the state of all learning. The delta carries:

```text
source relation
+ behavior or interpretation that caused the loss
+ corrected method
+ affected effect class
+ retained unknown or invalidator
+ first later circumstance in which the correction should act.
```

An update can be revised, superseded, or retired. Monotonic improvement is not
assumed.

### 4.4 Independent installed lineages

An installed Project Kernel begins as a source-linked seed, then becomes part
of another project. Its later competences may develop in ways that the
originating authors cannot predict. The source repository can publish new
research, software, or optional updates, but it does not remain the semantic
controller of installed systems.

An external lineage can inform the shared research field only through an
explicit, attributable return: a contribution, comparative observation,
failure report, or transferable method. Local state, private context, and
unreviewed learning do not flow back by default. Divergence is therefore both
a product property and a research variable, not drift to be automatically
eliminated.

## 5. Hypotheses

### H1 — Trajectory-aware contextual reentry

Given the same base model and source access, a reentry formed from the earlier
subject, causally consequential intervening events, and current conditions
will improve source/owner fidelity and causal integration relative to flat
retrieval of the earlier subject, without increasing contamination from
irrelevant events.

### H2 — Competence assimilation

An owner-local competence delta will reduce reconstruction burden or error in
later non-identical tasks beyond the effect of retrieving the original
correction, appending it to a standing prompt, or leaving the competence
unchanged.

### H3 — Event-local composition

For tasks whose decisive relations cross competence owners, event-local
composition will improve result quality or possibility preservation relative
to a fixed skill router, while avoiding unnecessary activation and bounded
latency overhead.

### H4 — Paper-derived operational condensate

A small, source-linked condensate derived from a stable academic corpus may
reduce orientation latency while preserving causal fidelity better than either
no corpus or loading the complete corpus. This is a secondary systems
hypothesis. The Paper does not depend on the condensate, and the condensate is
not package content until an owner selects and tests that relation.

The MAIOS Project Kernel repository provides a public, inspectable
incarnation of the proposed relations. At the observed source revision

`9dbb014f62e9ab06a4c0dba7203adc3051faf531`.

This evidence supports only representation, implementation, and bounded
structural-verification claims. It does not show that every supported host has
used the Kernel semantically, that a real operator has accepted every
resultant, or that later non-identical work has assimilated the proposed
competence changes. The repository is a reference artifact for reproducible
study, not empirical validation of the theory.

## 7. Experimental programme

### 7.1 Study A: contextual reentry

Construct paired multi-turn project episodes that share an initial subject and
later return request. Insert both relevant and irrelevant intervening events.
Compare:

1. flat transcript or topic retrieval;
2. retrieval plus an extended standing prompt;
3. an explicit state-machine summary;
4. a trajectory-aware coherent cut.

Hold the model, tools, total source access, and token budget as constant as
practical. Blind evaluators score causal integration, source and owner
fidelity, irrelevant-event contamination, uncertainty calibration, and
whether a late source mutation is detected before effect.

### 7.2 Study B: competence assimilation

Select recurrent error classes with multiple non-isomorphic tasks. After a
training episode and causal correction, compare:

1. unchanged competence;
2. retrieval of the correction episode;
3. correction appended to a general prompt;
4. owner-local competence evolution.

Measure operator restatement, recurrence of the target error, transfer to new
task forms, correction burden, latency, and unintended overgeneralization. A
file change without a later behavioral difference is not assimilation.

### 7.3 Study C: competence composition

Use tasks whose success depends on relations from several domains, such as
source provenance, software behavior, public claim state, and effect
authority. Compare event-local composition with a fixed router, a predefined
agent stack, and a base model with the same tools and documents. Measure task
quality, missed material relations, unnecessary activations, possibility
collapse, latency, and correction burden.

### 7.4 Study D: independent lineages

Initialize several external project installations from the same released
seed, then expose them to different project histories. Observe which
competence changes remain local, which recur independently, and which can be
expressed as transferable contributions without copying private context.
This study tests whether shared constitutive relations can coexist with
unpredictable owner-local evolution.

### 7.5 Study E: Paper-derived condensates

Only after the academic corpus stabilizes enough to derive comparable forms,
test reentry with no corpus, the full paper corpus, and condensates of different
density. Measure orientation time and cost, causal fidelity, omission,
contamination, and comprehension by both human readers and AI systems.

### 7.6 Reproducibility and analysis

Pre-register task families, exclusion criteria, primary outcomes, model and
tool versions, context budgets, and analysis plans. Preserve prompts, source
snapshots, competence versions, event histories, outputs, evaluator rubrics,
and effect receipts where privacy permits. Report negative results and cases
in which a simpler baseline matches the Kernel condition.

Hierarchical analyses should treat task family, model, host, and evaluator as
sources of variance. Effect sizes and confidence intervals are more important
than one aggregate awareness score. No single metric is proposed as a proxy
for awareness.

## 8. Falsifiers and limitations

The framework should be narrowed or rejected if:

- ordinary retrieval matches trajectory-aware reentry under comparable
  sources and budgets;
- competence deltas do not alter later non-identical behavior beyond prompt
  or memory baselines;
- event-local composition adds abstraction or latency without changing
  results, fidelity, or possibility preservation;
- a simpler workflow or state model explains the observations with equal or
  greater predictive power;
- causal readback records corrections but fails to change the projected
  result;
- independently evolving installations require incompatible constitutive
  laws rather than situated forms of the same framework;
- the vocabulary cannot be operationalized without evaluators inferring the
  desired result from the labels themselves.

The current account also has substantial limitations. The formalization is a
transition schema rather than a mathematical theory. The boundary of a
competence may be ambiguous when one artifact participates in several owners.
Project histories can leak task identity into later evaluations. Human
operator curation may explain apparent system learning. Longitudinal studies
will be expensive, and changes in foundation models can dominate architectural
effects. The public reference implementation is developed by the same project
that proposes the framework, so independent replications are essential.

## 9. Discussion

The proposed Kernel is not an additional agent above the work. It is the
coupling among present field, situated competence, result, causal learning, and
reentry. This definition makes direct task performance part of the Kernel
rather than evidence that the Kernel was bypassed.

The strongest distinction is between **stored reflection** and **changed
competence**. A system can accumulate memories, documents, or skills without
changing the causal method that produces later results. Conversely, a compact
owner-local correction can materially change later behavior without requiring
a global architecture rewrite. The assimilation experiments are intended to
make this distinction observable.

The Paper and the Kernel can participate in each other without becoming the
same object. The Paper's primary function is academic: to expose the research
object, argument, prior work, formal relations, evidence, alternatives,
falsifiers, and limitations to scholarly scrutiny. A later machine-readable or
operational condensate is a derived artifact. The selected product direction
is also to make the reviewed academic corpus discoverable to a packaged coder;
the product owner may project the complete Paper, a verified source locator,
or a source-linked condensate without changing the scholarly manuscript. A
condensate or hot-path role should exist only if it improves a measured system
relation and remains replaceable.

This hierarchy also protects external evolution. An installation is not a
remote replica waiting for the central corpus to define its future. It is a
new situated lineage. Some lineages may remain close to the initial release;
others may form competences or purposes absent from the originating project.
The research field can study those differences, but it cannot know or govern
them in advance.

## 10. Conclusion

This paper proposes an AI Project Kernel as a falsifiable project-level
framework for connecting situated action, competence, causal readback,
learning, and contextual reentry. Its central claim is deliberately narrower
than a claim of consciousness or general self-improvement: real work can form
a resultant whose attributable causal difference changes the competence
available to later, non-identical work.

The proposal becomes scientifically useful only if it discriminates behavior
that retrieval, prompting, workflows, routers, or base-model capacity do not
explain as well. The next step is therefore empirical: run the paired studies,
publish the full negative and positive results, and let independent project
lineages test which relations remain stable and which must evolve.
